# サイト引き継ぎ一式

5サイトのソースと、GitHub・Vercel へ引き継ぐための手順をまとめたリポジトリです。
このリポジトリだけで引き渡しが完結します。

```
zeroone/         株式会社ゼロワン      hr-zeroone.com
hakata-techno/   株式会社博多テクノ    hakata-techno.tech
stepia/          ステピア              stepia.jp
tokai-system/    株式会社東海システム  （独自ドメインなし）
sendai-logic/    株式会社仙台ロジック  sendai-logic.com
```

各ディレクトリがそれぞれ独立したサイトです。ディレクトリ内の `README.md` に、
そのサイト固有のセットアップ手順・ページ構成を記載しています。

## ソースの受け取り方

**zip で一括ダウンロード**（約25MB・5サイト分）

https://github.com/yotakagi42/hp-handover/archive/refs/heads/main.zip

リポジトリページ右上の緑の **Code** ボタン → **Download ZIP** からも同じものが取得できます。
GitHub アカウントは不要です。

**git で取得する場合**

```bash
git clone https://github.com/yotakagi42/hp-handover.git
```

| サイト | 構成 | パッケージ | Node |
| --- | --- | --- | --- |
| zeroone | Vite + React 19 + TypeScript | npm | 20 以上 |
| hakata-techno | Next.js + TypeScript | pnpm | 24 以上 |
| stepia | Next.js 16 + TypeScript | npm | 24 以上 |
| tokai-system | Next.js 16 + TypeScript | pnpm | 20 以上 |
| sendai-logic | 静的HTML（Nuxt 3 で書き出し済み） | — | 不要 |

`sendai-logic` だけはビルド不要です。書き出し済みのファイルをそのまま配信します。

---

## 先に用意するもの

- **GitHub Organization**（または個人アカウント）— このリポジトリの受け取り先
- **Vercel アカウント** — 法人での商用利用は **Pro プラン（$20/月〜）** が必要です。Hobby プランは規約上、商用利用が認められていません
- **ドメインの DNS 管理権限** — 独自ドメインを持つ4サイトはいずれも Xserver のネームサーバーを使用しています。管理画面にログインできる担当者が必要です

## 引き継ぎ手順

上から順に実行します。`[制作側]` と `[貴社]` で作業者が切り替わります。

### 1. リポジトリを受け取る `[制作側] → [貴社]`

制作側がこのリポジトリを貴社の Organization へ移管します。

- リポジトリ → Settings → General → 最下部の Danger Zone → **Transfer ownership**
- 貴社側で移管を承認してください（GitHub から通知が届きます）

移管せず、貴社で新規リポジトリを作って push する方法でも構いません。
このリポジトリは公開されているため、招待を待たずにすぐ取得できます。

```bash
git clone https://github.com/yotakagi42/hp-handover.git
cd hp-handover
git remote set-url origin https://github.com/<貴社Org>/<リポジトリ名>.git
git push -u origin main
```

zip でダウンロードした場合は、展開したフォルダで `git init` してから push してください。

### 2. Vercel でインポートする `[貴社]`

**サイトごとに Vercel プロジェクトを1つずつ作ります。** 同じリポジトリを5回インポートし、
それぞれ Root Directory を変えるかたちです。

Add New → Project → このリポジトリを選択 → **Root Directory** に対象ディレクトリを指定します。

| Vercel プロジェクト | Root Directory |
| --- | --- |
| （ゼロワン用） | `zeroone` |
| （博多テクノ用） | `hakata-techno` |
| （ステピア用） | `stepia` |
| （東海システム用） | `tokai-system` |
| （仙台ロジック用） | `sendai-logic` |

- フレームワークプリセットは自動検出されます（Next.js または Vite）
- ビルドコマンド・出力ディレクトリはデフォルトのままで通ります
- pnpm のサイトは `pnpm-lock.yaml` を見て自動的に pnpm が使われます
- 環境変数の設定は不要です（5サイトとも使用していません）
- **仙台ロジックはビルド不要**です。Framework Preset に `Other` を選び、Build Command は空欄、Output Directory は `.`（ディレクトリ直下）を指定してください。同ディレクトリの `vercel.json` にルーティング設定が含まれています

ビルドが完了すると `プロジェクト名.vercel.app` の URL が発行されます。
**この時点ではまだ独自ドメインを接続しないでください。**

### 3. 表示を確認する `[貴社]`

発行された `.vercel.app` の URL で、現在公開中のサイトと見比べてください。

- 全ページの表示（トップ、会社情報、採用情報など）
- 画像の欠けがないか
- スマートフォン幅での表示
- お問い合わせフォームの動作

> **ここが分岐点です。**
> 問題が見つかった場合は次へ進まず、制作側にご連絡ください。
> ドメインを切り替えた後に問題が出ると、公開中のサイトが壊れた状態になります。

### 4. ドメインを付け替える `[制作側] → [貴社]`

**ここだけサイトが数分間停止します。**
同じドメインを2つの Vercel アカウントに同時登録できないため、制作側が外してから貴社が追加する順序になります。
双方が対応できる時間帯に実施してください。

1. **制作側** — Vercel プロジェクトの Settings → Domains から該当ドメインを Remove
2. **貴社** — ご自身のプロジェクトの Settings → Domains で同じドメインを Add

DNS は既に Vercel を向いているため、**Xserver 側の設定変更は原則不要**です。
Vercel 内部での付け替えだけで済み、数分で復旧します。

> **所有確認を求められた場合**
> Vercel がドメイン所有の確認として TXT レコードの追加を求めることがあります。
> Xserver の DNS レコード設定で、Vercel の画面に表示される `_vercel` の TXT 値を追加し、
> 反映後に Vercel 側で Refresh すると検証が通ります。

東海システムは独自ドメインを持たないため、**手順4・5は不要**です（詳細は後述）。

### 5. SSL と www を整える `[貴社]`

ドメイン追加後、Vercel が Let's Encrypt の証明書を自動発行します。通常は数分で `https://` が有効になります。

Vercel が要求する DNS レコードは次の形です。

| 種別 | ホスト | 値 |
| --- | --- | --- |
| A | `@` | `76.76.21.21` |
| CNAME | `www` | `cname.vercel-dns.com` |

> **ゼロワン・ステピアは要対応**
> この2サイトは `www` 付きでアクセスすると、サイトではなく **Xserver の初期ページが表示されます**。
> `www` が Xserver のサーバーを指したままになっているためです。
> 上記の CNAME レコードを設定して解消してください。博多テクノは設定済みで対応不要です。

### 6. 旧環境を停止する `[制作側]`

貴社の環境で本番ドメインが正常に動作していることを確認してから、制作側の Vercel プロジェクトを削除します。

- 数日〜1週間は残しておくことを推奨します（切り戻しの保険になります）
- 削除後の復旧はリポジトリからの再デプロイになります

## サイト別の申し送り

### 東海システム — ドメインについて

`tokai-system.net` は現在、制作側とは別の Vercel アカウントが保持しており、別事業の会社サイトを配信しています。
このソースはドメインに接続されていないため、**手順4・5は不要**です。

### 東海システム — ロゴ画像 `[要確認]`

`tokai-system/public/logo.png` は社名の文字要素を含まない抽象的な幾何学マークで、制作時の暫定素材の可能性があります。
正式なロゴがある場合は差し替えてください。

### 博多テクノ — ファビコン `[推奨]`

`favicon.ico` が Next.js の標準アイコンのままの可能性があります。
ブラウザのタブに表示されるため、自社のアイコンへの差し替えを推奨します。

### ステピア — 未使用の動画素材

`stepia/public/videos/` の `kv.mp4`（5.9MB）と `kv-original.mp4`（8.4MB）は、
現在のサイトから参照されていない未使用素材です。`<video>` タグ自体が存在しません。
今後使う予定がなければ削除して構いません。

### 仙台ロジック — ロゴとファビコン `[要確認]`

ヘッダーのロゴ（インライン SVG）と `favicon.ico` は、制作時の参考サイト由来のものがそのまま使われています。
自社のロゴデータに差し替えることを推奨します。ロゴは `index.html` ほか各ページの `<svg id="logosvg">`、
ファビコンは `favicon.ico` の置き換えで対応できます。

### 仙台ロジック — robots.txt `[要確認]`

`robots.txt` が `Disallow: /`（全ページのクロール拒否）のままです。制作時の設定と思われます。
検索エンジンに載せる運用であれば解除してください。あわせて `sitemap.xml` の設置も検討ください。

### ステピア・ゼロワン — 依存パッケージの更新 `[推奨]`

ステピアで19件、ゼロワンで7件の既知の脆弱性が `npm audit` で検出されています。
大半はフレームワーク本体に起因するもので、解消には現在の依存範囲を超えるバージョン更新が必要です。
運用開始後、計画的な更新をご検討ください。

## 引き継ぎ後の運用

### サイトの更新

`main` ブランチに push すると、Vercel が自動でビルドして本番に反映します。
別ブランチへの push はプレビュー環境が作られ、本番には影響しません。

モノレポ構成のため、**変更のあったディレクトリに対応するプロジェクトだけがビルドされます**
（Vercel の Root Directory 設定により自動で判定されます）。

```bash
# ゼロワン・ステピア
cd zeroone && npm install && npm run dev

# 博多テクノ・東海システム
cd hakata-techno && pnpm install --frozen-lockfile && pnpm dev

# 仙台ロジック（ビルド不要・静的配信）
cd sendai-logic && python3 -m http.server 3141
```

各サイトの詳細は、それぞれのディレクトリ内の `README.md` を参照してください。

### 費用

Vercel Pro プランは1メンバーあたり月 $20 です。帯域やビルド時間が規定量を超えると追加課金が発生しますが、
5サイトはいずれも静的生成が中心の小規模構成のため、通常運用で超過する可能性は低い見込みです。

ドメインの更新費用は Xserver 側で継続して発生します。管理者アカウントの引き継ぎもあわせてご確認ください。

## つまずきやすい点

**ドメインを追加すると「別のアカウントで使用中」と出る**
制作側のプロジェクトからまだ削除されていません。手順4の順序どおり、削除を待ってから追加してください。

**ドメインが「Invalid Configuration」のまま変わらない**
DNS の反映待ちか、TXT による所有確認が未完了です。数分待って Vercel の画面で Refresh し、
解消しなければ手順5の DNS 値を確認してください。

**ローカルでは通るのに Vercel でビルドが失敗する**
Node のバージョン違いが原因のことが多いです。各サイトの `.nvmrc` と、
Vercel の Project Settings → Node.js Version が合っているか確認してください。

**Vercel が想定と違うディレクトリをビルドする**
Root Directory の指定漏れです。Project Settings → General → Root Directory を確認してください。

**切り替えたらサイトが表示されなくなった**
制作側のプロジェクトが残っていれば、ドメインを戻すことで数分で復旧できます。
手順6で「数日は残す」としているのはこのためです。

**HTTPS で証明書エラーが出る**
証明書の発行が完了していません。追加直後は数分かかります。
10分以上続く場合は DNS が Vercel を正しく向いているか確認してください。
