# サイト引き継ぎ一式

5サイトのソースと、更新の進め方をまとめたリポジトリです。

```
zeroone/         株式会社ゼロワン      hr-zeroone.com
hakata-techno/   株式会社博多テクノ    hakata-techno.tech
stepia/          ステピア              stepia.jp
tokai-system/    株式会社東海システム  （独自ドメインなし）
sendai-logic/    株式会社仙台ロジック  sendai-logic.com
```

各ディレクトリがそれぞれ独立したサイトです。ディレクトリ内の `README.md` に、
そのサイト固有のセットアップ手順・ページ構成を記載しています。

| サイト | 構成 | パッケージ | Node |
| --- | --- | --- | --- |
| zeroone | Vite + React 19 + TypeScript | npm | 20 以上 |
| hakata-techno | Next.js + TypeScript | pnpm | 24 以上 |
| stepia | Next.js 16 + TypeScript | npm | 24 以上 |
| tokai-system | Next.js 16 + TypeScript | pnpm | 20 以上 |
| sendai-logic | 静的HTML（Nuxt 3 で書き出し済み） | — | 不要 |

`sendai-logic` だけはビルド不要です。書き出し済みのファイルをそのまま配信します。

## ソースの受け取り方

**zip で一括ダウンロード**（約25MB・5サイト分）

https://github.com/yotakagi42/hp-handover/archive/refs/heads/main.zip

リポジトリページ右上の緑の **Code** ボタン → **Download ZIP** からも同じものが取得できます。
GitHub アカウントは不要です。

**git で取得する場合**

```bash
git clone https://github.com/yotakagi42/hp-handover.git
```

## 引き継ぎの進め方

サイトは現在 Vercel で稼働し、ドメインは XServer で管理しています。
どちらのアカウントにも貴社の担当者を招待しますので、
**サーバーの引っ越しもドメインの移管も発生しません。サイトが止まる時間もありません。**

### 1. Vercel チームへの参加 `[貴社]`

制作側から招待メールが届きます。受け取ってアカウントを作成し、チームに参加してください。
参加すると、5サイトのプロジェクトと稼働状況が見えるようになります。

### 2. GitHub リポジトリへの参加 `[貴社]`

このリポジトリの書き込み権限をお渡しします。GitHub アカウントをお持ちでなければ作成のうえ、
アカウント名を制作側にお伝えください。招待を送ります。

### 3. XServer アカウントへの参加 `[貴社]`

ドメインの管理画面です。こちらも招待をお送りします。参加すると、
DNS レコードの設定や、ドメインの更新手続きを貴社側で行えるようになります。

### 4. 自動デプロイの接続 `[制作側]`

Vercel の各プロジェクトをこのリポジトリに接続します。接続後は、
**リポジトリの `main` ブランチに push すると自動でビルドされ、本番に反映されます。**

この作業は制作側で行います。完了したらご連絡します。

## サイトの更新方法

`main` ブランチに push するだけです。別のブランチに push した場合はプレビュー環境が作られ、
本番には影響しません。いきなり本番を変えたくないときはこちらを使ってください。

変更したディレクトリに対応するサイトだけがビルドされます。
`zeroone/` を直しても他の4サイトは再ビルドされません。

```bash
# ゼロワン・ステピア
cd zeroone && npm install && npm run dev

# 博多テクノ・東海システム
cd hakata-techno && pnpm install --frozen-lockfile && pnpm dev

# 仙台ロジック（ビルド不要・静的配信）
cd sendai-logic && python3 -m http.server 3141
```

各サイトの詳細は、それぞれのディレクトリ内の `README.md` を参照してください。

## サイト別の申し送り

### 東海システム — 公開状況

`tokai-system.net` は現在、別の事業者が保持しており、別の会社のサイトが表示されています。
制作したソースはドメインに接続されていない状態です。公開するには別途ドメインの手配が必要です。

### 東海システム — ロゴ画像 `[要確認]`

`tokai-system/public/logo.png` は社名の文字要素を含まない抽象的な図形で、制作時の仮素材の可能性があります。
正式なロゴがあれば差し替えてください。

### 仙台ロジック — ロゴとファビコン `[要確認]`

ヘッダーのロゴ（インライン SVG）と `favicon.ico` は、制作時の参考サイト由来のものがそのまま使われています。
自社のロゴデータへの差し替えを推奨します。ロゴは各ページの `<svg id="logosvg">`、
ファビコンは `favicon.ico` の置き換えで対応できます。

### 仙台ロジック — robots.txt `[要確認]`

`robots.txt` が `Disallow: /`（全ページのクロール拒否）のままです。制作時の設定と思われます。
検索エンジンに載せる運用であれば解除してください。あわせて `sitemap.xml` の設置もご検討ください。

### ゼロワン・ステピア — www でアクセスすると表示されない

この2サイトは `www` 付きでアクセスすると、サイトではなく XServer の初期ページが表示されます。
`www` が XServer のサーバーを指したままになっているためです。解消するには、
XServer の DNS レコード設定（手順3で参加した管理画面）に次を追加してください。

| 種別 | ホスト | 値 |
| --- | --- | --- |
| CNAME | `www` | `cname.vercel-dns.com` |

博多テクノと仙台ロジックは設定済みで、対応は不要です。

### ステピア — 未使用の動画素材

`stepia/public/videos/` の `kv.mp4`（5.9MB）と `kv-original.mp4`（8.4MB）は、
現在のサイトから参照されていない未使用素材です。`<video>` タグ自体が存在しません。
今後使う予定がなければ削除して構いません。

### ステピア・ゼロワン — 依存パッケージの更新 `[推奨]`

ステピアで19件、ゼロワンで7件の既知の脆弱性が `npm audit` で検出されています。
大半はフレームワーク本体に起因するもので、解消には現在の依存範囲を超えるバージョン更新が必要です。
運用開始後、計画的な更新をご検討ください。

## つまずきやすい点

**push したのにサイトが変わらない**
`main` 以外のブランチに push していないか確認してください。`main` 以外はプレビュー環境が作られるだけで、
本番には反映されません。Vercel のダッシュボードでビルドが成功しているかも確認できます。

**ローカルでは動くのに Vercel でビルドが失敗する**
Node のバージョン違いが原因のことが多いです。各サイトの `.nvmrc` と、
Vercel の Project Settings → Node.js Version が合っているか確認してください。

**Vercel が想定と違うディレクトリをビルドする**
Root Directory の設定です。Project Settings → General → Root Directory で、
対象のサイト名（`zeroone` など）が指定されているか確認してください。

**間違えて本番を壊してしまった**
Vercel のダッシュボードから、過去のデプロイに戻せます。
対象のデプロイを開いて Promote to Production を選んでください。数十秒で戻ります。
